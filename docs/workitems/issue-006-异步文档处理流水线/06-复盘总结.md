# 复盘总结

## 本次收获

- 学会把“上传成功”和“处理完成”拆成两个不同的业务结果：前者属于 API 写入责任，后者属于后台任务责任。
- 学会在 Go 中用 `channel + goroutine + context` 组织一个最小可用后台 worker，并给它补上 `Close` 生命周期。
- 学会用显式任务模型表达阶段状态、失败原因和重试次数，而不是把所有信息都堆进单个文档字段。
- 为后续 `#7` 留下了可复用的 parser / chunker / indexer 边界，降低后续返工风险。

## 这次踩到的坑

- 当前主工作区停在早期 `codex/bootstrap-repo`，一开始读取不到 `#5` 的文件，需要先从 `origin/main` 创建新的隔离工作树。
- 在 `zsh` 里把变量命名成 `path` 会污染命令搜索路径，导致 `git` 等命令失效。
- 直接使用默认 Go 构建缓存目录会触发沙箱权限问题，需要显式指定工作区内或临时目录的 `GOCACHE`。

## 后续优化方向

- 把内存队列替换为可持久化的消息中间件，补齐多实例下的幂等与抢占控制。
- 把内存索引替换为真实向量索引，实现 `#7` 的检索召回。
- 为处理任务补充更多观测字段，如耗时、失败分类和最近一次重试发起人。
