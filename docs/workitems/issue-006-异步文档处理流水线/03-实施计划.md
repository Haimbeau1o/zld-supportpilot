# 实施计划

## 总体策略

先补齐领域模型和任务/切块边界，再用 TDD 落地处理任务执行逻辑，最后补 HTTP 和应用装配，确保每一层都能独立验证。

## 分阶段拆解

1. 扩展 knowledge 领域模型、任务模型和仓储接口
2. 先写失败测试，补服务层的入队、处理、失败和重试逻辑
3. 增加内存队列与后台 worker，验证异步行为
4. 暴露任务查询与重试 HTTP 接口
5. 更新应用装配、README、验证记录、工作日志和复盘文档

## 风险与控制

- 风险：后台 goroutine 影响测试稳定性
  - 控制：服务逻辑支持同步 `ProcessTask`，异步 worker 单独测试并在 app 中提供 `Close`
- 风险：为 #7 过度设计
  - 控制：只沉淀 parser/chunker/indexer 三段式边界，不提前实现检索服务
- 风险：上传接口行为变化影响 #5 既有测试
  - 控制：保持上传返回成功语义不变，新增处理元数据而不破坏原契约
