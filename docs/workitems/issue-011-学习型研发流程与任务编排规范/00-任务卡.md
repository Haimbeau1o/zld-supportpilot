# 任务卡

## 基本信息

- Issue 编号：#11（预期）
- Issue 标题：主线：建立学习型研发流程与任务编排规范
- 类型：主线
- 所属阶段：M0 - 方法与协作基础

## 背景与问题

当前仓库已经具备基础 Go 骨架和 GitHub 流程入口，但还缺少一套统一的方法层标准，无法保证后续每个 Issue 都有完整的研究过程、中文文档、依赖分析和规范化沉淀。

## 目标

建立一套面向本仓库的学习型研发流程，使后续所有需求都能够以“需求分析 → 调研 → 设计 → 实施 → 验证 → 复盘”的方式推进。

## 范围

### 包含

- 文档模板
- Issue 并发性分析
- 执行波次规划
- 通用 skill 和项目 skill
- 中文 Issue / PR 模板

### 不包含

- 具体业务功能实现
- 数据库表和 API 的业务开发

## 前置依赖

- 无

## 并发性判断

- 是否可独立并行：否
- 如果不能并行，阻塞点是什么：它本身是后续所有业务 Issue 的方法前置
- 如果可以并行，可与哪些 Issue 同步推进：无
- 是否需要后续融合 Issue：是，需要与 #12 #13 在 #14 收口

## 输出物

- 方法层模板目录
- 协作文档
- 双层 skill
- 中文化 Issue / PR 模板

## 验收标准

- 仓库内有统一模板和协作文档
- skill 可以描述并发性分析与融合策略
- 后续业务 Issue 能基于这套方法推进
