# 方案设计

## 设计目标

让进入仓库的后续执行能快速知道：当前阶段、模块边界、Issue 类型和依赖关系。

## 模块边界

- skill 只绑定本仓库，不抽象成通用方法
- 项目 references 聚焦模块边界与路线图

## 数据流 / 时序

- 识别当前阶段 → 确认当前 Issue 类型 → 校验 workitem 是否存在 → 根据模块边界和依赖关系决定执行方式

## 接口或数据结构草案

- skill 的固定上下文包括：模块边界、阶段约束、Issue 编排规则、当前并发性结论

## 错误处理与边界条件

- 如果仓库路线图变化但 skill 不更新，后续编排会失真
- 如果模块边界不清，融合 Issue 容易变成杂项包

## 中文注释计划

本 Issue 主要是项目 skill 与 references，不涉及业务代码；中文说明重点是模块边界、阶段约束与常见误用。
