# 实施计划

## 总体策略

先扩展 ticket 领域模型和仓储接口，再通过 TDD 落地评论、内部备注和审计事件服务逻辑，最后补 HTTP 接口和应用层验证。

## 分阶段拆解

1. 扩展 ticket 模型、评论与审计事件仓储
2. 先写失败测试，再实现评论写入和时间线查询
3. 补指派 / 状态流转自动审计事件
4. 暴露 HTTP 接口并验证权限边界
5. 回填 README 与工作文档

## 风险与控制

- 风险：时间线模型过度复杂
  - 控制：先以统一列表输出，保留最小可用字段
- 风险：权限边界在时间线拼装时漂移
  - 控制：所有过滤和可见性判断统一放在服务层
- 风险：审计记录被调用方遗漏
  - 控制：在 ticket service 内部自动写入审计事件
