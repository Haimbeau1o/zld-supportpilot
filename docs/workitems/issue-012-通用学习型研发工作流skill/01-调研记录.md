# 调研记录

## 调研目标

把“学习型研发”从口头约定沉淀成可复用方法。

## 调研问题

- 如何把每个 Issue 的学习过程固定下来？
- 如何让 skill 具备 issue 并发性分析能力？
- 如何避免 skill 变成过度叙事的过程文档？

## 资料来源

| 来源 | 链接/位置 | 关注点 | 结论摘要 |
| --- | --- | --- | --- |
| `superpowers:writing-skills` | 本地 skill | skill 的触发条件、固定结构与反模式 | skill 需要强调触发条件、固定输出和反模式 |
| `superpowers:brainstorming` | 本地 skill | 如何收敛需求与分阶段呈现 | 先明确目标，再逐段收敛与验证 |
| 当前仓库已有 M0 文档 | 本仓库 docs | 缺少可复用方法论抽象 | 需要把方法层从仓库规则抽象成 skill |

## 候选方案比较

| 方案 | 优点 | 缺点 | 适用条件 | 是否采用 |
| --- | --- | --- | --- | --- |
| 只保留仓库文档 | 直接、低成本 | 无法跨项目复用 | 单仓库演示 | 否 |
| 只写 skill，不保留仓库模板 | 方法更抽象 | 仓库内追踪性不足 | 偏工具型项目 | 否 |
| 仓库模板 + 通用 skill | 既可追踪又可复用 | 前期整理成本高 | 学习型长期项目 | 是 |

## 最终决策

采用“仓库模板 + 通用 skill”组合，让方法既能在仓库内执行，也能跨项目复用。

## 决策理由

这样既能约束当前项目，也能为未来的 Go / AI 项目提供统一工作流。
