# 任务卡

- Issue 编号：#24
- Issue 标题：主线：持久化底座升级（PostgreSQL + 文档持久化）
- 类型：主线
- 所属阶段：M4 - 内用业务闭环化

## 背景与问题

当前仓库已经具备认证、工单、知识库、RAG 和 AI 工单辅助等完整业务能力，但数据层仍以 memory repository 为主。只要进程重启，用户、工单、知识库、文档元数据和知识切块都会丢失，这意味着系统更像“演示工程”，而不是“内部试运行系统”。

要把 `ZLD SupportPilot` 往真实内用业务推进，第一步不是继续加更多 AI 功能，而是先让关键数据具备最小持久化能力。只有持久化底座稳定，后续统一受理入口、反馈回流、知识候选审核、通知触达和内测发布才有意义。

## 目标

为身份、工单、知识库、文档处理链路补齐 PostgreSQL 持久化，为原始文档补齐最小可用的文件系统持久化方案，并在应用装配层支持 memory / postgres 模式切换。

## 范围

### 包含

- PostgreSQL 连接配置与启动期 schema 初始化
- identity / ticket / knowledge 核心 repository 的 PostgreSQL 适配
- 文档原始内容的文件系统持久化
- `internal/app` 中 memory / postgres 的运行模式切换
- README / `.env.example` / 工作文档同步更新
- 关键设计意图与边界条件的中文注释

### 不包含

- Redis / Kafka / 分布式事务
- MinIO / S3 正式对象存储接入
- 队列持久化与任务恢复调度器
- 多活部署与跨地域容灾
