## 执行顺序

1. 先写 config / app / storage 的失败测试，锁定模式切换行为；
2. 再写 PostgreSQL 平台层与 repository 的失败测试；
3. 用最小 migration + repository 让测试转绿；
4. 最后再补 README 和工作文档。

## 风险点

- repository 数量较多，若 schema 设计和服务契约不一致，会造成连锁回归；
- 当前 service 没有上下文参数，PostgreSQL adapter 需要内部统一使用 `context.Background()`；
- 若组织 ID 仍使用进程内自增，postgres 模式下重启后会有重复风险，需要改成稳定唯一策略；
- 若只持久化文档元数据、不持久化任务与 chunk，会导致 RAG 重启后丢失能力。

## 联调点 / 融合点

- 需要验证 memory 模式不回归；
- 需要验证 postgres 模式缺失配置时能给出清晰错误；
- 需要验证文件存储与 PostgreSQL 元数据配合下，知识处理链路仍可工作；
- 需要为后续 #25 / #27 保留稳定的数据底座。
