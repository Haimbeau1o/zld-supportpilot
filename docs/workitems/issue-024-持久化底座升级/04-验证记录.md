## 手工验证建议

### 本地 memory 模式

1. `cp .env.example .env`
2. 保持 `APP_PERSISTENCE_MODE=memory`
3. 执行 `go run ./cmd/api`
4. 完成注册、建单、知识库上传，确认接口行为与基线一致

### 本地 postgres + filesystem 模式

1. `docker compose -f deployments/docker/docker-compose.yml up -d postgres`
2. 设置：
   - `APP_PERSISTENCE_MODE=postgres`
   - `DOCUMENT_STORAGE_MODE=filesystem`
   - `DOCUMENT_STORAGE_ROOT=./data/documents`
3. 执行 `go run ./cmd/api`
4. 完成注册、建单、知识库上传
5. 重启应用后再次查询用户、工单、知识库、文档、处理任务与切块，确认元数据仍可读取
6. 检查 `DOCUMENT_STORAGE_ROOT` 目录，确认原始文档文件已落盘

## 边界情况验证

- `postgres` 模式缺少 `POSTGRES_DSN`：启动失败，避免静默回退到 memory
- `filesystem` 模式目录不存在：保存时自动创建目录树
- 文档处理时间字段为空：以数据库 `NULL` 保存，避免把“未开始/未完成”误写成零值业务时间
- 服务重启后再次注册租户：组织 ID 改为随机唯一生成，避免与历史组织冲突

## 失败与修正

- 初始 RED 阶段先暴露了配置字段缺失、启动未校验 DSN、文件系统存储不存在、PostgreSQL 平台层缺失等问题
- 编写 SQL mock 测试时出现过链式调用换行语法错误，已在测试文件中修正
- `sed` 替换一度误伤变量名，已回滚为精确替换并重新执行 targeted tests
