## 手工验证

1. 启动服务后调用 `POST /api/v1/auth/register`，应返回 `201`，并返回 `user_id`、`organization_id`、`role`
2. 调用 `POST /api/v1/auth/login`，应返回 `200`，并返回 `access_token`、`token_type`、`expires_in`
3. 使用 `Authorization: Bearer <access_token>` 调用 `GET /api/v1/auth/me`，应返回当前用户身份与权限集合
4. 未带 `Authorization` 访问 `GET /api/v1/auth/me`，应返回 `401`

## 边界情况验证

- 重复注册：服务层测试覆盖，返回明确冲突错误
- 密码错误：服务层测试覆盖，统一返回凭证错误语义
- 令牌篡改：令牌测试覆盖，解析失败
- 默认角色分配：注册链路覆盖，未显式指定时分配 `tenant_admin`
- 缺少 Bearer Token：中间件测试覆盖，返回 `401`

## 失败与修正

- 初始 HTTP 路由只有 `healthz`，新增 `NewMuxWithDependencies` 做显式依赖注入，同时保留 `NewMux` 以兼容纯骨架启动
- 初始配置结构缺少认证字段，补充 `AUTH_SIGNING_KEY` 与 `AUTH_TOKEN_TTL_SECONDS` 后，应用装配可以稳定创建身份模块依赖
