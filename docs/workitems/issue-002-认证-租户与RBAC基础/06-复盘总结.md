# 复盘总结

## 本次学到的内容

- 认证基础阶段最重要的不是“功能多”，而是先稳定身份边界与权限上下文
- 角色到权限映射比直接写死角色判断更适合作为后续模块的公共底座

## 关键取舍

- 选择 JWT Access Token，而不是更重的 Session / Redis 方案
- 选择 interface-first + 内存适配，先稳定结构，再考虑数据库实现

## 遇到的问题

- 当前仓库还没有正式的数据层与迁移体系，数据库一步到位会扩大当前 Issue 范围
- 如果权限命名现在随意定义，后面工单和知识库会跟着混乱

## 下次可优化点

- 在实现前先固定一份权限命名表
- 后续可在身份基础稳定后再补数据库持久化适配

## 对后续 Issue 的影响

- `#3` 与 `#5` 将复用本 Issue 的身份上下文与权限入口
- 如果本 Issue 边界稳定，后续两条业务主线可以安全并行
