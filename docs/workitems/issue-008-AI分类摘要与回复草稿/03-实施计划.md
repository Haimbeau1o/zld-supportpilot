# 实施计划

## 总体策略

先在 `ai` 模块中补齐 ticket assist 服务与结果模型，再通过 TDD 落地“读取工单 + 复用知识回答 + 记录 AI 内部备注”的主链路，最后补 HTTP 接口、应用装配和文档验证。

## 分阶段拆解

1. 定义 AI ticket assist 模型与依赖边界
2. 先写失败测试，再实现分类建议、摘要与回复草稿生成
3. 接入 ticket 内部备注，落地 AI 执行记录
4. 暴露 HTTP 接口并验证权限边界
5. 回填 README 与工作文档

## 风险与控制

- 风险：AI 输出模型过重，拖慢本阶段交付
  - 控制：先做单接口统一输出，不拆多种操作类型
- 风险：AI 结果直接写回工单主数据，造成越权
  - 控制：明确只返回建议，不自动更新 ticket 主模型
- 风险：执行记录落点不清晰
  - 控制：优先复用 internal note，后续再视需要抽独立模型
