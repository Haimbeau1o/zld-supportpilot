## 背景与问题

当前系统已经具备工单主流程、知识库上传处理、RAG 问答、统一 AI 受理和答案反馈回流，但“工单处理经验如何回到知识库”这条链路仍然缺失。

对于一个真实内部服务台产品，知识库不能只依赖手工上传文档。更有价值的路径是：

- 一线工单被解决
- 解决结论被整理成知识候选
- 经过审核后沉淀入库
- 后续同类问题可被问答直接命中

这也是“系统越用越聪明”的关键业务闭环。

## 目标

建立“已解决工单 -> 知识候选 -> 审核通过 -> 入知识处理链路”的最小真实闭环。

## 范围

### 包含

- 知识候选模型
- 从已解决工单生成知识候选
- 候选列表
- 审核通过 / 驳回
- 审核通过后触发知识文档入库与处理流水线
- 相关测试、README 与工作文档更新

### 不包含

- 完全无审核自动上线
- 复杂知识运营后台
- 基于 LLM 的自动结论提炼
