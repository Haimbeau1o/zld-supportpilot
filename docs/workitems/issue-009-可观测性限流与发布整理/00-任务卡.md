## 背景与问题

当前仓库已经具备认证、工单、知识库、RAG 回答和 AI 辅助等主链路能力，但“能跑起来”还不等于“像真实后端系统”。如果缺少请求关联、结构化日志、基础指标、限流保护和演示文档，项目在简历叙事、联调排障、接口演示和上线收尾上都会显得不完整。

对“智能服务台”这类 AI + 传统后端混合项目来说，工程化能力不是附属物，而是决定项目真实度的重要部分：一方面要能看见请求经过了什么链路、慢在哪里、失败在哪里；另一方面要在高成本接口前放置最基础的保护边界，避免 AI 问答、文档上传或登录接口被无约束打爆。

## 目标

围绕当前最小可演示系统，补齐一套“足够真实、不过度设计”的工程化收尾能力：

- 为关键路径补齐请求 ID、结构化访问日志和基础 HTTP 指标；
- 为高成本或高风险接口补齐最小限流保护；
- 为本地演示、面试讲解和阶段发布准备清晰的操作说明。

## 范围

### 包含

- 请求 ID 生成 / 透传与响应头回写
- 关键接口结构化访问日志
- 基础 HTTP 指标采集与只读暴露
- 限流边界选择、实现与响应约定
- README 与演示 / 发布说明补充
- 对应工作文档沉淀、中文注释与验证记录

### 不包含

- 引入 OpenTelemetry、Prometheus、Jaeger 等完整外部观测栈
- 多实例分布式限流（当前阶段仍为单进程演示系统）
- Kubernetes、容器编排、真实云上发布流水线
- 完整 SLO / 告警平台建设
