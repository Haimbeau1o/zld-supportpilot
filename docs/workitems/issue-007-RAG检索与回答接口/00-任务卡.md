# 任务卡

## 基本信息

- Issue 编号：#7
- Issue 标题：融合：RAG 检索与回答接口
- 类型：融合
- 所属阶段：M3 - AI 与工程化

## 背景与问题

`#5` 和 `#6` 已经分别完成知识库上传与异步处理流水线，系统现在已经具备“文档 -> chunk” 的基础输入，但还没有把这些 chunk 真正用于问答。缺少统一的检索与回答接口，意味着知识库只能“存”，不能“答”，也无法体现 AI 应用与传统后端链路的融合价值。

## 目标

围绕知识库建立最小可用的 RAG 回答接口：先检索相关 chunk，再生成带引用的回答，并在检索置信度不足时明确降级为“无法可靠回答”。

## 范围

### 包含

- 检索服务抽象
- 向量检索适配（当前阶段采用内存向量检索）
- 回答生成服务与引用返回
- 低置信度降级策略
- AI HTTP 接口、应用装配、测试和中文注释
- 对应工作文档沉淀

### 不包含

- 外部真实向量数据库
- 外部真实大模型调用
- 多轮会话记忆
- 工单自动分类、摘要和回复草稿（属于 #8）
- 运营看板、Prompt 管理后台

## 前置依赖

- #5 主线：知识库与文档上传
- #6 并行：异步文档处理流水线

## 并发性判断

- 是否可独立并行：否
- 如果不能并行，阻塞点是什么：必须依赖 #6 产出的 ready 文档与 chunk 索引边界
- 如果可以并行，可与哪些 Issue 同步推进：不建议与 #8 并行编码，需先稳定回答接口契约
- 是否需要后续融合 Issue：是，后续将与 #8 的分类、摘要与回复草稿能力融合

## 验收标准

- 回答接口可以返回答案、引用和置信度
- 检索与生成职责边界清晰，后续可替换为真实向量库与大模型
- 当检索置信度不足时，接口返回明确降级结果，而不是伪造答案
