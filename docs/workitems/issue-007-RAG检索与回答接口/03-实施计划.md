# 实施计划

## 总体策略

先补齐 `ai` 模块的领域模型与检索 / 生成边界，再通过 TDD 落地回答服务和 HTTP 接口，最后回填应用装配和验证文档。

## 分阶段拆解

1. 定义回答模型、检索抽象和向量检索实现
2. 实现 AI 服务的回答、引用和降级逻辑
3. 增加知识模块对 chunk 的只读访问能力
4. 暴露 HTTP 接口并完成 app 装配
5. 全量验证并回填文档

## 风险与控制

- 风险：没有真实向量库导致“向量检索”表达不够完整
  - 控制：采用可解释的哈希向量 + 余弦相似度方案，重点展示接口与评分逻辑
- 风险：回答生成过于模板化
  - 控制：把 `AnswerGenerator` 单独抽象出来，为真实 LLM 接入预留边界
- 风险：模块边界模糊
  - 控制：只让 AI 服务读取 ready chunk，不让 AI 直接碰对象存储或处理任务
