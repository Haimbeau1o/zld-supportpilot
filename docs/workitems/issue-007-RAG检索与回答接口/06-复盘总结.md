# 复盘总结

## 本次收获

- 学会把 RAG 拆成“知识准备 -> 检索 -> 生成 -> 降级”四段职责，而不是把所有逻辑揉进单一接口。
- 学会用可解释的哈希向量和余弦相似度，在没有外部依赖的情况下先稳定检索边界。
- 学会把低置信度降级做成显式 API 语义，避免在简历项目里出现“能答但不可靠”的黑盒行为。
- 学会让 AI 模块消费 `knowledge` 的 ready chunk，而不是直接耦合到上传或处理流水线内部。

## 这次踩到的坑

- `#7` 虽然逻辑上依赖 `#6`，但因为 `PR #18` 已经合并，所以基线不该继续叠在旧分支上，而应重新从 `origin/main` 起分支。
- `knowledge.Service` 原本只负责处理链路，没有暴露 chunk 读取边界，导致 `app` 装配 AI 服务时第一次编译失败。
- 在当前阶段引入真实向量库或外部 LLM 会放大环境依赖，反而削弱了“边界设计 + 工程落地”的主线表达。

## 后续优化方向

- 将内存向量检索替换为真实向量数据库和 embedding 服务。
- 将模板式回答生成器替换为基于 `pkg/llm.Provider` 的真实模型实现。
- 在 `#8` 中复用当前回答与引用边界，为工单分类、摘要和回复草稿提供知识增强能力。
