## 手工验证

1. 启动服务后，先通过 `POST /api/v1/auth/register` 与 `POST /api/v1/auth/login` 获取访问令牌
2. 使用 Bearer Token 调用 `POST /api/v1/knowledge/bases`，应返回 `201` 与新知识库元数据
3. 使用 Bearer Token 和 multipart/form-data 调用 `POST /api/v1/knowledge/bases/{id}/documents`，应返回 `201` 与文档元数据、上传状态和存储键
4. 使用 Bearer Token 调用 `GET /api/v1/knowledge/bases`、`GET /api/v1/knowledge/bases/{id}/documents`、`GET /api/v1/knowledge/documents/{id}`，应返回租户内可见数据

## 边界情况验证

- 无知识写权限创建知识库：服务层测试覆盖，返回 `forbidden`
- 上传空文件：服务层测试覆盖，返回明确输入错误
- 未登录访问知识库接口：HTTP 层测试覆盖，返回 `401`
- 跨租户访问：服务层通过 `OrganizationID` 边界限制，当前阶段未单独补 HTTP 用例
- 真实对象存储故障：代码已保留存储失败错误语义，当前阶段未单独补错误注入测试

## 失败与修正

- 初始路由装配只支持认证与 ticket 依赖，knowledge 接入后已扩展 `RouteDependencies` 以承载多模块路由注册
- 如果上传链路直接依赖真实对象存储，本地开发和测试会被外部环境绑死；当前阶段改为存储接口抽象 + 内存适配，先稳定主边界
