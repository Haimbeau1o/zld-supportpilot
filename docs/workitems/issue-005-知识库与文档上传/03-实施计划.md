## 执行顺序

1. 先稳定知识库、文档元数据与上传状态模型
2. 再把权限边界、存储接口与元数据记录落到 service 层
3. 然后通过 HTTP 接口暴露知识库创建与文档上传链路
4. 最后回填应用装配、验证记录和复盘

## 风险点

- 如果在主线阶段直接接真实 MinIO，会让实现与测试被外部环境绑死
- 如果文档状态现在不固定，后续 #6 的异步处理会反向改主模型
- 如果上传权限和知识库归属校验只写在 HTTP 层，后续 worker 或内部调用会出现权限漂移

## 联调点 / 融合点

- 与 `identity` 模块联调：确认 `IdentityContext` 足以支撑知识库读写权限判断
- 与 `#6` 的融合点：复用稳定的文档状态字段、元数据和存储键
- 与 `#7` 的融合点：后续检索和回答链路基于文档元数据与知识库边界接入
- 详细拆解见：`docs/plans/2026-03-07-knowledge-upload-implementation-plan.md`
