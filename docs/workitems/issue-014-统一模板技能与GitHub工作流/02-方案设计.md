# 方案设计

## 设计目标

让方法层形成闭环：仓库模板负责沉淀，skill 负责指导，GitHub 负责执行入口。

## 模块边界

- 本 Issue 不新增通用方法或项目事实，重点在统一与校验

## 数据流 / 时序

- 收集 #12 和 #13 的输出 → 对齐仓库模板与 GitHub 模板 → 更新路线图和依赖分析 → 细化 PR 说明

## 接口或数据结构草案

- 统一术语包括：主线 / 并行 / 融合、7 件套、执行波次、中文注释、依赖分析

## 错误处理与边界条件

- 如果只更新 GitHub 模板，不更新 skill，会导致执行入口与方法规则脱节
- 如果只更新 docs，不更新 PR 描述，评审者难以理解 M0 的价值

## 中文注释计划

本 Issue 仍是文档与流程融合，不涉及业务代码；重点是统一术语和操作方式。
