## 背景与问题

`#25` 已经把“问答”和“建单”统一成一个 AI 受理入口，但系统仍然缺少“答案是否真的解决问题”的业务回流能力。若没有反馈沉淀，系统就无法回答三个关键问题：

- AI 直接回答的命中率到底如何
- 哪些回答虽然给出了结果，但用户仍然需要人工介入
- 哪些场景应该被快速升级成正式工单

对于一个真实内部服务台产品，这部分能力决定了 AI 不只是“会回答”，而是“能进入业务闭环”。

## 目标

围绕统一 AI 受理结果，补齐最小可用的反馈闭环：

- 用户可以对一次 AI 受理结果提交 `已解决 / 未解决 / 不准确` 三类反馈
- 系统能够根据 `未解决` 自动执行升级规则，避免问题停留在“回答过但没人跟进”
- 后台可以查看基础反馈统计，为后续知识回流和运营优化提供依据

## 范围

### 包含

- AI intake 结果留痕
- answer feedback 领域模型与 repository
- feedback API 与 stats API
- `未解决` 场景下的自动升级规则

- 反馈驱动的知识自动改写
