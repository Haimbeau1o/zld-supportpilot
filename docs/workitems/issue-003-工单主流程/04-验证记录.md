## 手工验证

1. 启动服务后，先通过 `POST /api/v1/auth/register` 与 `POST /api/v1/auth/login` 获取访问令牌
2. 使用 Bearer Token 调用 `POST /api/v1/tickets`，应返回 `201` 与新工单主字段
3. 使用 Bearer Token 调用 `GET /api/v1/tickets`，终端用户只应看到自己的工单
4. 使用具备工单写权限的身份调用 `POST /api/v1/tickets/{id}/assign` 与 `POST /api/v1/tickets/{id}/status`，应返回更新后的工单

## 边界情况验证

- 终端用户只能看到自己的工单：服务层与 HTTP 层测试覆盖
- 非法状态流转：服务层测试覆盖，返回明确错误
- 未登录访问工单接口：HTTP 层测试覆盖，返回 `401`
- 跨租户访问：服务层通过 `OrganizationID` 边界限制，当前阶段未单独补 HTTP 用例
- 缺少工单写权限时执行指派 / 流转：服务层通过 `PermissionTicketWrite` 限制

## 失败与修正

- 初始路由装配只支持认证依赖，无法承载 ticket 路由；已扩展为 `RouteDependencies`，同时保留原有 `NewMuxWithDependencies` 兼容接口
- HTTP 测试如果完全依赖注册 / 登录创建同租户多角色用户，会过早耦合成员管理能力；因此测试中直接签发同租户身份令牌，把验证焦点放回工单主流程本身
