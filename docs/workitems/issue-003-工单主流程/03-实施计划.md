## 执行顺序

1. 先稳定工单模型与状态机规则
2. 再把权限边界落到 service 层
3. 然后通过 HTTP 接口暴露主链路
4. 最后回填应用装配、验证记录和复盘

## 风险点

- 如果主模型里把评论、审计等协作能力一起塞进来，会直接侵入 #4 的范围
- 如果状态流转规则不先固定，后续 HTTP 与审计实现会反复返工
- 如果查询范围规则写在 HTTP 层而不是 service 层，后续其他入口会出现权限漂移

## 联调点 / 融合点

- 与 `identity` 模块联调：确认 `IdentityContext` 足以支撑工单权限判断
- 与 `#4` 的融合点：复用稳定的工单主模型、动作入口与状态变更边界
- 与 `#8` 的融合点：后续 AI 摘要、分类和回复草稿基于工单主流程接口挂载
