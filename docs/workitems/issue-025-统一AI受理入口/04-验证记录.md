## 手工验证建议

1. `cp .env.example .env`
2. 执行 `go run ./cmd/api`
3. 登录并创建知识库
4. 调用 `POST /api/v1/ai/intakes`
5. 观察两类返回：
   - 知识充分：`result_type=answered`
   - 知识不足：`result_type=ticket_created`，并返回 `ticket_id`

## 边界情况验证

- 问题为空：返回 `400 invalid_ai_request`
- 请求体非法 JSON：返回 `400 invalid_request`
- 未登录访问：返回 `401 unauthorized`
- 低置信度：自动建单并返回 `ticket_id`
- 高置信度：不建单，直接返回答案与引用

## 失败与修正

- HTTP 层 RED 阶段命中 `404`，说明统一入口路由未注册，后续通过新增 handler 与 route 修复
- 集成测试初次失败是请求 JSON 拼接错误，修正后验证通过
- 统一受理建单测试中，stub 需要改为指针接收，才能在测试里稳定记录建单输入
