# 调研记录

## 现状确认

### 工单侧

- `ticket.Service.AssignTicket()` 已稳定承担工单分派职责
- `ticket.Service.TransitionTicketStatus()` 已稳定承担状态流转职责
- 当前服务层会记录审计事件，但不会做任何通知动作

### AI 侧

- `ai.Service.HandleUnifiedIntake()` 在知识不足时会直接建单
- `ai.Service.SubmitAnswerFeedback()` 在 `unresolved` 时会升级为人工跟进工单
- 当前升级动作没有触达能力

### 身份侧

- 用户模型已有 `Email`
- 现有 identity repository 仅支持 `FindByEmail`
- 若要给分派 / 状态变化发邮件，需要补 `FindByID` 以便按 userID 解析邮箱

## 初步结论

最合适的实现方式不是把通知写在 HTTP handler，而是挂在 `ticket` / `ai` 服务内部，通过独立通知模块旁路执行。
